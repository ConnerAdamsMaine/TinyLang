# TIDE Chat

TIDE Chat is available at `/chat.html` for authenticated accounts. Each channel has a permanent `TIDE-C-XXXXXX` public identifier, which can be resolved through `GET /api/v1/chat/channels/public/{public_id}`; the resolver only returns channels the current account can access, and does not reveal private channels or direct messages to unauthorized accounts. Sending messages, opening or blocking direct messages, reacting, reporting, deleting, and using WebSockets requires a session established by a linked GitHub, Discord, or X identity; server-side session and channel authorization still apply. Public channels support paginated history, flat replies, a bounded set of reactions, WebSocket delivery, @mentions, and search across public channels and private channels the account can access. Users can open one-to-one direct messages by TIDE User ID or create a group direct message with 2-9 other active users (10 participants total maximum). Group membership is fixed at creation; the exact same participant set returns the existing group channel, regardless of who opens it. Group creation is rejected if any participant pair has blocked one another. Group messages notify every other active member. Group participants are not editable after creation. One-to-one blocks apply to one-to-one conversations; all members of an existing group conversation continue to see messages posted to that group. In one-to-one channels, only the two participants have access, and each new message adds an inbox notice for the other participant. Either participant can block or unblock the other; a block prevents new one-to-one direct-message creation and sending in either direction while preserving access to existing history. Search is rate-limited, bounded to 50 results, and backed by a trigram index; it excludes deleted, expired, archived, and inaccessible-channel messages. Mentions create a private inbox notice only for active accounts with access to that channel. Message identifiers are sent through PostgreSQL notifications so connected replicas can load and broadcast committed messages without placing their text in notification payloads. Channel visibility and private memberships are checked on the server for history, search, sends, WebSockets, reactions, and reports. Designated chat moderators receive an isolated report queue and can redact messages reported by participants; moderators do not receive live access to direct-message channels. Users can delete their own messages for 15 minutes after posting.

Connections are limited to 3 per account and 1,000 per process; messages are limited to 4,000 characters/16 KiB and 30 per account per minute. A slow connection is disconnected when it falls behind the bounded broadcast buffer and must reload history before reconnecting. The browser uses capped exponential reconnection and refuses to queue new messages while the WebSocket send buffer exceeds 256 KiB; failed sends preserve the user's draft. Chat messages are ordinary mutable data, separate from the immutable governance ledger, and expire after 90 days through a periodic cleanup task.

Limitations: group membership cannot be edited after creation; one-to-one blocking does not hide messages in shared group conversations. Message editing, configurable retention, and a moderator management UI are not implemented. Cross-instance fan-out is verified end-to-end by `tests/chat-multi-replica/run.ps1`, which runs two real web containers against one disposable PostgreSQL and asserts a message posted through replica A arrives on replica B's WebSocket, and by a live browser check driving the real chat UI on both replicas (a message sent in replica A's browser appeared in replica B's browser without reload; this check caught and fixed a flattened `/api/auth/me` response mismatch in the client). Load and reconnect/backpressure behavior at capacity still require a staging deployment. Search currently provides substring matching rather than ranked full-text search. Moderator grants and private channel memberships require explicit database administration. Chat discussion is not an official engineering decision unless it is recorded through an authorized TIDE decision workflow.
